* 目标：将当前业务错误码风格转换为标准RESTful风格

## 设计决策总结

- 错误码策略：纯RESTful（不保留数字code，仅用字符串错误类型）
- 多字段验证错误：数组结构
- 成功响应结构：Data + Message
- 文件处理：删除code.go，创建error_types.go

## HTTP状态码语义定义

### 成功状态码（2xx）

| HTTP状态码 | 语义 | 适用场景 |
|-----------|------|---------|
| **200 OK** | 请求成功 | GET查询、PUT更新、PATCH部分更新、登录成功 |
| **201 Created** | 资源创建成功 | POST创建新资源（注册用户、创建帖子） |
| **204 No Content** | 成功但无内容返回 | DELETE删除资源 |

### 客户端错误（4xx）

| HTTP状态码 | 语义 | 适用场景 |
|-----------|------|---------|
| **400 Bad Request** | 请求参数错误 | 缺少必填字段、字段格式错误、JSON解析失败 |
| **401 Unauthorized** | 未认证 | 缺少认证token、token无效、登录失败 |
| **403 Forbidden** | 无权限 | 已认证但权限不足 |
| **404 Not Found** | 资源不存在 | 查询的用户不存在、API路径错误 |
| **409 Conflict** | 资源冲突 | 用户名已存在、邮箱已注册 |
| **422 Unprocessable Entity** | 无法处理 | 参数验证失败（语义错误） |
| **429 Too Many Requests** | 请求过多 | 限流、频率超限 |

### 服务器错误（5xx）

| HTTP状态码 | 语义 | 适用场景 |
|-----------|------|---------|
| **500 Internal Server Error** | 服务器内部错误 | 数据库错误、未预期的异常 |
| **503 Service Unavailable** | 服务不可用 | 服务维护、过载 |

**完整内容：**

#+BEGIN_SRC go
package controllers

import "net/http"

// ==================== 错误类型定义 ====================
// 使用字符串标识错误类型，比数字code更语义化
// 符合RESTful标准，无数字错误码

const (
    // ==================== 参数验证错误 ====================
    // HTTP 400 Bad Request
    
    ErrValidation      = "validation_error"      // 参数验证失败
    ErrInvalidParam    = "invalid_param"         // 请求参数错误
    ErrInvalidJSON     = "invalid_json"          // JSON解析失败
    ErrMissingField    = "missing_field"         // 缺少必填字段
    
    // ==================== 认证错误 ====================
    // HTTP 401 Unauthorized
    
    ErrUnauthorized    = "unauthorized"          // 未认证
    ErrInvalidToken    = "invalid_token"         // Token无效
    ErrTokenExpired    = "token_expired"         // Token过期
    ErrLoginFailed     = "login_failed"          // 登录失败
    
    // ==================== 权限错误 ====================
    // HTTP 403 Forbidden
    
    ErrForbidden       = "forbidden"             // 权限不足
    ErrAccessDenied    = "access_denied"         // 拒绝访问
    
    // ==================== 资源错误 ====================
    // HTTP 404 Not Found
    
    ErrNotFound        = "not_found"             // 资源不存在
    ErrUserNotExist    = "user_not_exist"        // 用户不存在
    ErrPostNotExist    = "post_not_exist"        // 帖子不存在
    
    // ==================== 冲突错误 ====================
    // HTTP 409 Conflict
    
    ErrConflict        = "conflict"              // 资源冲突
    ErrUserExists      = "username_exists"       // 用户名已存在
    ErrEmailExists     = "email_exists"          // 邮箱已注册
    
    // ==================== 限流错误 ====================
    // HTTP 429 Too Many Requests
    
    ErrRateLimit       = "rate_limit"            // 请求频率超限
    
    // ==================== 服务器错误 ====================
    // HTTP 500 Internal Server Error
    
    ErrInternal        = "internal_error"        // 服务器内部错误
    ErrDatabase        = "database_error"        // 数据库错误
    ErrThirdParty      = "third_party_error"     // 第三方服务错误
)

// ==================== HTTP状态码映射 ====================

// getHTTPStatus 根据错误类型返回对应的HTTP状态码
// 这是RESTful风格的核心：HTTP状态码有明确语义
func getHTTPStatus(errorType string) int {
    switch errorType {
    // 参数验证错误 -> 400
    case ErrValidation, ErrInvalidParam, ErrInvalidJSON, ErrMissingField:
        return http.StatusBadRequest
    
    // 认证错误 -> 401
    case ErrUnauthorized, ErrInvalidToken, ErrTokenExpired, ErrLoginFailed:
        return http.StatusUnauthorized
    
    // 权限错误 -> 403
    case ErrForbidden, ErrAccessDenied:
        return http.StatusForbidden
    
    // 资源不存在 -> 404
    case ErrNotFound, ErrUserNotExist, ErrPostNotExist:
        return http.StatusNotFound
    
    // 资源冲突 -> 409
    case ErrConflict, ErrUserExists, ErrEmailExists:
        return http.StatusConflict
    
    // 限流 -> 429
    case ErrRateLimit:
        return http.StatusTooManyRequests
    
    // 服务器错误 -> 500
    case ErrInternal, ErrDatabase, ErrThirdParty:
        return http.StatusInternalServerError
    
    // 默认：服务器错误
    default:
        return http.StatusInternalServerError
    }
}

// ==================== 错误消息映射（可选） ====================

// errorMsgMap 错误类型的默认消息
// 可用于快速调用，无需每次都传入message
var errorMsgMap = map[string]string{
    ErrValidation:      "参数验证失败",
    ErrInvalidParam:    "请求参数错误",
    ErrInvalidJSON:     "JSON解析失败",
    ErrMissingField:    "缺少必填字段",
    ErrUnauthorized:    "未认证，请先登录",
    ErrInvalidToken:    "Token无效",
    ErrTokenExpired:    "Token已过期",
    ErrLoginFailed:     "用户名或密码错误",
    ErrForbidden:       "权限不足",
    ErrAccessDenied:    "拒绝访问",
    ErrNotFound:        "资源不存在",
    ErrUserNotExist:    "用户不存在",
    ErrPostNotExist:    "帖子不存在",
    ErrConflict:        "资源冲突",
    ErrUserExists:      "用户名已存在",
    ErrEmailExists:     "邮箱已注册",
    ErrRateLimit:       "请求频率超限，请稍后再试",
    ErrInternal:        "服务器内部错误",
    ErrDatabase:        "数据库操作失败",
    ErrThirdParty:      "第三方服务错误",
}

// getErrorMsg 获取错误类型的默认消息
func getErrorMsg(errorType string) string {
    msg, ok := errorMsgMap[errorType]
    if !ok {
        return "服务器错误"
    }
    return msg
}

**完整内容：**

#+BEGIN_SRC go
package controllers

import (
    "net/http"
    
    "github.com/gin-gonic/gin"
)

// ==================== 响应结构定义 ====================

// SuccessResponse 成功响应结构
// 符合RESTful标准，简洁清晰
type SuccessResponse struct {
    Data    interface{} `json:"data"`              // 业务数据
    Message string      `json:"message,omitempty"` // 提示消息（可选）
}

// ErrorResponse 单一错误响应结构
type ErrorResponse struct {
    Error   string `json:"error"`            // 错误类型标识（字符串）
    Message string `json:"message"`          // 用户友好的错误消息
    Field   string `json:"field,omitempty"`  // 错误字段（可选，用于单字段验证错误）
}

// ValidationErrorResponse 多字段验证错误响应结构
// 用于参数验证时多个字段同时错误
type ValidationErrorResponse struct {
    Error  string       `json:"error"`   // 错误类型："validation_error"
    Errors []FieldError `json:"errors"`  // 多字段错误列表
}

// FieldError 单字段错误结构
type FieldError struct {
    Field   string `json:"field"`   // 字段名
    Message string `json:"message"` // 错误消息
}

// ==================== 成功响应函数 ====================

// Success 成功响应（200 OK）
// 使用场景：GET查询、PUT更新、PATCH部分更新、登录成功等
// 示例：Success(ctx, user)
func Success(ctx *gin.Context, data interface{}) {
    ctx.JSON(http.StatusOK, SuccessResponse{
        Data: data,
    })
}

// SuccessWithMessage 成功响应（带消息）
// 示例：SuccessWithMessage(ctx, "登录成功", user)
func SuccessWithMessage(ctx *gin.Context, message string, data interface{}) {
    ctx.JSON(http.StatusOK, SuccessResponse{
        Data:    data,
        Message: message,
    })
}

// Created 资源创建成功响应（201 Created）
// 使用场景：POST创建新资源（注册用户、创建帖子等）
// RESTful标准：创建资源应返回201状态码
// 示例：Created(ctx, user)
func Created(ctx *gin.Context, data interface{}) {
    ctx.JSON(http.StatusCreated, SuccessResponse{
        Data:    data,
        Message: "创建成功",
    })
}

// CreatedWithMessage 资源创建成功响应（自定义消息）
// 示例：CreatedWithMessage(ctx, "注册成功", user)
func CreatedWithMessage(ctx *gin.Context, message string, data interface{}) {
    ctx.JSON(http.StatusCreated, SuccessResponse{
        Data:    data,
        Message: message,
    })
}

// NoContent 成功响应但无内容（204 No Content）
// 使用场景：DELETE删除资源
// RESTful标准：删除成功通常返回204（无内容）
// 示例：NoContent(ctx)
func NoContent(ctx *gin.Context) {
    ctx.Status(http.StatusNoContent)  // 仅设置状态码，无body
}

// ==================== 错误响应函数 ====================

// Fail 错误响应（自动根据错误类型设置HTTP状态码）
// 核心函数：根据error_type自动映射HTTP status code
// 示例：Fail(ctx, ErrUserExists, "用户名已存在") -> HTTP 409
// 示例：Fail(ctx, ErrUnauthorized, "请先登录") -> HTTP 401
func Fail(ctx *gin.Context, errorType string, message string) {
    httpStatus := getHTTPStatus(errorType)
    
    ctx.JSON(httpStatus, ErrorResponse{
        Error:   errorType,
        Message: message,
    })
}

// FailWithDefaultMsg 错误响应（使用默认消息）
// 示例：FailWithDefaultMsg(ctx, ErrUserExists) -> HTTP 409, message="用户名已存在"
func FailWithDefaultMsg(ctx *gin.Context, errorType string) {
    httpStatus := getHTTPStatus(errorType)
    message := getErrorMsg(errorType)
    
    ctx.JSON(httpStatus, ErrorResponse{
        Error:   errorType,
        Message: message,
    })
}

// FailWithField 错误响应（带字段信息）
// 用于单字段验证错误，提供字段名
// 示例：FailWithField(ctx, ErrValidation, "用户名长度不符合要求", "username")
//      -> HTTP 400, {"error":"validation_error","message":"...","field":"username"}
func FailWithField(ctx *gin.Context, errorType string, message string, field string) {
    httpStatus := getHTTPStatus(errorType)
    
    ctx.JSON(httpStatus, ErrorResponse{
        Error:   errorType,
        Message: message,
        Field:   field,
    })
}

// FailValidation 多字段验证错误响应
// 用于validator验证时多个字段同时错误
// 示例：FailValidation(ctx, []FieldError{
//      {Field: "username", Message: "用户名长度不符"},
//      {Field: "password", Message: "密码强度不足"},
// })
//      -> HTTP 400, {"error":"validation_error","errors":[...]}
func FailValidation(ctx *gin.Context, errors []FieldError) {
    ctx.JSON(http.StatusBadRequest, ValidationErrorResponse{
        Error:  ErrValidation,
        Errors: errors,
    })
}

// ==================== 快速调用函数 ====================
// 提供常用错误的快速调用，简化代码

// BadRequest 400 Bad Request（快速调用）
// 示例：BadRequest(ctx, "请求参数格式错误")
func BadRequest(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusBadRequest, ErrorResponse{
        Error:   ErrInvalidParam,
        Message: message,
    })
}

// Unauthorized 401 Unauthorized（快速调用）
// 示例：Unauthorized(ctx, "请先登录")
func Unauthorized(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusUnauthorized, ErrorResponse{
        Error:   ErrUnauthorized,
        Message: message,
    })
}

// Forbidden 403 Forbidden（快速调用）
// 示例：Forbidden(ctx, "权限不足")
func Forbidden(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusForbidden, ErrorResponse{
        Error:   ErrForbidden,
        Message: message,
    })
}

// NotFound 404 Not Found（快速调用）
// 示例：NotFound(ctx, "用户不存在")
func NotFound(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusNotFound, ErrorResponse{
        Error:   ErrNotFound,
        Message: message,
    })
}

// Conflict 409 Conflict（快速调用）
// 示例：Conflict(ctx, "用户名已存在")
func Conflict(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusConflict, ErrorResponse{
        Error:   ErrConflict,
        Message: message,
    })
}

// InternalError 500 Internal Server Error（快速调用）
// 示例：InternalError(ctx, "服务器内部错误")
// 注意：message应该对用户友好，不应暴露内部细节
func InternalError(ctx *gin.Context, message string) {
    ctx.JSON(http.StatusInternalServerError, ErrorResponse{
        Error:   ErrInternal,
        Message: message,
    })
}

// InternalErrorDefault 500 内部错误（使用默认消息）
// 示例：InternalErrorDefault(ctx)
func InternalErrorDefault(ctx *gin.Context) {
    ctx.JSON(http.StatusInternalServerError, ErrorResponse{
        Error:   ErrInternal,
        Message: getErrorMsg(ErrInternal),
    })
}
#+END_SRC

// SignUp 用户注册
// RESTful风格：创建资源返回201 Created
func SignUp(ctx *gin.Context) {
    param := new(models.ParamSignUp)
    
    // 1. 参数验证
    if err := ctx.ShouldBind(param); err != nil {
        zap.L().Error("参数验证失败", zap.Error(err))
        
        // 处理validator错误
        errs, ok := err.(validator.ValidationErrors)
        if !ok {
            // JSON解析失败或其他非validator错误
            BadRequest(ctx, "请求参数格式错误")  // HTTP 400
            return
        }
        
        // Validator错误：收集所有字段错误
        var fieldErrors []FieldError
        for _, fieldErr := range errs {
            var msg string
            if trans != nil {
                msg = errs.Translate(trans)
            } else {
                msg = fieldErr.Error()
            }
            fieldErrors = append(fieldErrors, FieldError{
                Field:   fieldErr.Field(),
                Message: msg,
            })
        }
        
        // 返回多字段验证错误（HTTP 400）
        FailValidation(ctx, fieldErrors)
        return
    }

    // 2. 业务处理
    if err := logic.SignUp(param); err != nil {
        zap.L().Error("用户注册失败", zap.Error(err))
        
        // 根据业务错误判断
        // TODO: logic层应返回明确错误类型，便于精确判断
        Conflict(ctx, "用户名已存在")  // HTTP 409
        return
    }
    
    // 3. 成功响应：创建资源成功，返回201
    Created(ctx, nil)  // HTTP 201 Created
}
#+END_SRC

// Login 用户登录
// RESTful风格：登录成功返回200 OK，失败返回401 Unauthorized
func Login(ctx *gin.Context) {
    param := new(models.ParamLogin)

    // 1. 参数解析
    if err := ctx.ShouldBindJSON(param); err != nil {
        zap.L().Error("参数解析失败", zap.Error(err))
        BadRequest(ctx, "JSON格式错误")  // HTTP 400
        return
    }

    // 2. 业务验证
    if err := logic.Login(param); err != nil {
        zap.L().Error("登录验证失败", zap.Error(err))
        Unauthorized(ctx, "用户名或密码错误")  // HTTP 401
        return
    }
    
    // 3. 成功响应
    Success(ctx, nil)  // HTTP 200 OK
}
#+END_SRC

| **用户已存在** | HTTP 200 + gin.H | HTTP 409 + Conflict |
| **登录失败** | HTTP 200 + code=401 | HTTP 401 + Unauthorized |
| **注册成功** | HTTP 200 + gin.H | HTTP 201 + Created |

### Logic层错误类型定义

**当前问题：**
logic层返回笼统的`error`，无法区分具体错误类型。

**建议改进：**

#+BEGIN_SRC go
// logic/user.go
import "errors"

var (
    ErrUserExists     = errors.New("用户已存在")
    ErrUserNotExist   = errors.New("用户不存在")
    ErrInvalidPassword = errors.New("密码错误")
)

func SignUp(p *models.ParamSignUp) error {
    exist, err := mysql.CheckUserExist(p.Username)
    if err != nil {
        return err  // 数据库错误
    }
    if exist {
        return ErrUserExists  // 明确的业务错误
    }
    // ...
}
#+END_SRC

**Controller层处理：**

#+BEGIN_SRC go
if err := logic.SignUp(param); err != nil {
    zap.L().Error("注册失败", zap.Error(err))
    
    // 根据错误类型判断
    if errors.Is(err, logic.ErrUserExists) {
        Conflict(ctx, "用户名已存在")  // HTTP 409
    } else {
        InternalErrorDefault(ctx)  // HTTP 500
    }
    return
}
#+END_SRC

## RESTful风格优势总结

| 维度 | RESTful（新方案） | 国内业务错误码 |
|------|------------------|--------------|
| **HTTP语义** | 完全符合HTTP标准 | HTTP始终200，语义丢失 |
| **状态码表达** | 400/401/409等有明确语义 | 数字code无HTTP语义 |
| **错误标识** | 字符串类型（username_exists） | 数字code（20001） |
| **国际标准** | 符合RESTful国际标准 | 国内特定做法 |
| **HTTP生态** | CDN缓存、代理正确处理 | HTTP 200无法利用缓存规则 |
| **监控识别** | 传统HTTP监控可识别错误 | 需自定义监控逻辑 |
| **文档标准** | Swagger/OpenAPI友好 | 需自定义文档 |
| **浏览器工具** | DevTools直观显示错误 | 都显示200，误导 |

## 注意事项

1. **前端适配：** 前端需要处理不同的HTTP状态码
2. **Logic层错误：** 应返回明确错误类型，便于Controller判断
3. **安全考虑：** 500错误不应暴露内部细节，仅记录到日志
4. **测试覆盖：** 需要测试各种HTTP状态码场景
5. **文档更新：** API文档应标注正确的HTTP状态码
